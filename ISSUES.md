# Issues

## Reporting

Use the GitHub [issue tracker](https://github.com/belfry-project/belfry/issues) for bugs and feature requests, and fill out as much of the issue form as possible. Version information (`/api/v2/ping/`), the install method and an accurate reproducing scenario are critical to identifying the problem. Problems with the operator or the Helm chart belong in [belfry-operator](https://github.com/belfry-project/belfry-operator/issues) and [helm-charts](https://github.com/belfry-project/helm-charts/issues).

Never report a security vulnerability in a public issue; see the [security policy](https://github.com/belfry-project/.github/blob/main/SECURITY.md). For questions on installing, migrating and upgrading, see the [Belfry documentation](https://belfry-project.github.io/docs/) first.

Before opening a new issue, please search the existing issues to see if your problem has already been reported. If you have extra detail, add a comment; otherwise, rather than posting a "me too" comment, give the issue a "thumbs up" reaction.

### UI issues

When reporting UI issues, screenshots and any error messages from the web browser's console help. Browser extensions and plugins can cause problems too; mentioning them speeds up the analysis.

### API and backend issues

For the API and backend services, please capture all the logs you can from the time the problem occurred.

## How issues are resolved

Belfry is maintained by volunteers. Issues are labeled by type and component and higher-impact problems (for example ones that break existing functionality for many users) are usually handled first, so please be patient if yours takes a while.
