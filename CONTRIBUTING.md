# Contributing to Belfry

Thanks for helping. The process (issues, pull requests against `main`, commit messages, CI, code of conduct) is the same for every Belfry repository and is described in the organization's [contributing guide](https://github.com/belfry-project/.github/blob/main/CONTRIBUTING.md); the [website](https://belfry-project.github.io/docs/contributing/) has more detail. This file only covers what is specific to this repository.

- Open pull requests against the `main` branch (there is no `devel` branch) and fill in the pull request template.
- No Developer Certificate of Origin (`--signoff`) is required.
- Keep diffs small: Belfry stays close to upstream AWX so upstream changes can still be merged. Avoid reformatting or renaming code you do not need to change.
- Report vulnerabilities privately, as described in the [security policy](https://github.com/belfry-project/.github/blob/main/SECURITY.md), never in a public issue.

## Development environment

The development environment uses Docker and docker compose to provide the services and databases Belfry needs, and bind-mounts the local source tree into the development container so changes are picked up while it runs. See [tools/docker-compose/README.md](./tools/docker-compose/README.md) for how to build the `awx_devel` image and start it.

Once it runs, the web interface is at [https://localhost:8043](https://localhost:8043) and the API at [https://localhost:8043/api/](https://localhost:8043/api/). [Create an admin user](./tools/docker-compose/README.md#create-an-admin-user) if needed. `make docker-clean` removes the containers and images again.

The web UI is developed in [belfry-ui](https://github.com/belfry-project/belfry-ui).

### API documentation

To build the OpenAPI (Swagger) specification, run:

```bash
(container)/awx_devel$ make swagger
```

This writes `swagger.json` with the API specification.

### Checks

- Lint and format: `ruff check` and `ruff format --check` (configuration in `pyproject.toml`), or `(container)/awx_devel$ make format`.
- Unit tests: `(container)/awx_devel$ make test`.
- `make pre-commit` installs a pre-commit hook that runs these checks before each commit. Executable files in a `pre-commit-user` directory at the root of the repository are run as extra hooks; the variable `CHANGED_FILES` holds the files in the commit.

CI on GitHub Actions runs the same checks, and they must pass before a pull request is merged. Write tests for new functionality and bug fixes.

### Translations

Translations are generated by an automated process and the `.po` files are overwritten, so pull requests that add or change translations are not accepted. Please open an issue instead.
